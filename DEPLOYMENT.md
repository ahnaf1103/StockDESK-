# StockDesk deployment and inventory update guide

## What changed

This package now has one canonical inventory format: `data/stockdesk-inventory.csv`. The file uses the columns `model, config, brand, type, start, in, out, available, note`, matching the latest supplied inventory file. The PHP app can export the same format from `api/export.php` and can import it through `api/import.php`.

The installer schema was also aligned with the PHP API. Database credentials are read from `config.php`, which is generated by `install.php`; they are no longer duplicated in the API helper.

## Initial hosting

1. Upload the contents of `StockDesk_Fresh_Full_Installer/` into the hosting document root, normally `htdocs`.
2. Open `/install.php`, enter the MySQL credentials from the hosting panel, and complete installation.
3. Delete `install.php` and `setup.sql` from the public server after installation.
4. Log in with `admin@stockdesk.app` and password `admin`, then change the password through the account-management flow if enabled.

## Updating inventory from the supplied file

The normal update is a **full snapshot replacement**, so rows removed from the CSV do not remain as stale inventory rows.

After logging in, upload `data/stockdesk-inventory.csv` to `api/import.php` with a multipart POST. The endpoint defaults to replacement mode:

```bash
curl -b cookies.txt -X POST \
  -F 'file=@data/stockdesk-inventory.csv' \
  'https://YOUR-DOMAIN.example/api/import.php?replace=1'
```

The response reports `imported` and `skipped` row counts. To append instead of replace, use `replace=0`:

```bash
curl -b cookies.txt -X POST \
  -F 'file=@my-additional-stock.csv' \
  'https://YOUR-DOMAIN.example/api/import.php?replace=0'
```

The endpoint requires the same logged-in session and CSRF setup as other write operations. For a browser-based admin workflow, the simplest next UI addition is a file picker that posts to this endpoint and displays the returned counts; the existing local demo import remains available for offline use.

## Exporting current app data

Export the canonical CSV:

```text
https://YOUR-DOMAIN.example/api/export.php?format=csv
```

Export a JSON backup containing inventory and history:

```text
https://YOUR-DOMAIN.example/api/export.php?format=backup
```

Both endpoints require login. Keep downloaded backups private.

## Safer hosting updates

For a code-only update, replace the application files but keep the server-generated `config.php` and the database. Always take a JSON backup first. Do not commit or publicly expose `config.php`; it contains database credentials. If the archive is shared, rotate the database password in the hosting panel and rerun the installer configuration only if necessary.
